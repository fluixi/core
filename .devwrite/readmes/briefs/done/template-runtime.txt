package:  @fluixi/template-runtime
audience: someone putting Fluixi in a page with a script tag and no bundler
one-line: compiles html`` in the browser, so a page with no build step can use templates
measured: the CDN build is 103 KB, 33 KB gzipped
verified: every example below was run in a browser
do-not-claim: that this is the way to build an app. The compiled path produces
          smaller output; this exists for pages that cannot run a build.
          do not claim it works under a strict Content-Security-Policy: it
          evaluates the code the compiler emits, so it needs 'unsafe-eval'.
structure: four short sections, no headings beyond the ones named.
  1. what it is: the compiler normally replaces html`` at build time, and the tag
     the runtime carries throws if it ever runs. This package puts the same
     compile in front of the same runtime, so a page compiles its templates as it
     renders. One implementation, two moments.
  2. "From a script tag" — with this code block VERBATIM:
```html
<script src="https://unpkg.com/@fluixi/template-runtime/dist/cdn/fluixi.global.js"></script>
<script>
  const { html, render, signal, define } = Fluixi;

  function Counter() {
    const n = signal(0);
    return html`<button @click=${() => n.set(n() + 1)}>count: ${n}</button>`;
  }
  define({ Counter });

  render(() => html`<div><Counter /></div>`, document.getElementById('app'));
</script>
```
  3. "Components" — a bare <Counter /> resolves through define(), or from a global.
     Passing it as a hole, <${Counter} />, always works and needs no registration.
     A module-scoped component is not visible to a bare tag unless registered,
     because the compiled expression is evaluated in global scope.
  4. "What it costs" — the size above, and the unsafe-eval requirement.
