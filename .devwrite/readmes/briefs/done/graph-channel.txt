package:  @fluixi/vite-plugin — a new "## Reactive graph" section for the README, placed
          after the Options table and before License, plus one row for the options table
audience: someone running the dev server who wants the graph, and someone working on the
          framework itself
one-line: heading, three short paragraphs, one small code block, one table row
verified: end to end on examples/counter — GET /__fluixi/graph returned the app's own
          `count @ src/App.tsx:6` and `component Counter @ src/main.tsx:5`, and with
          external on, `revalidationVersion` from the router and `clientLocale` from i18n
do-not-claim: that it works in a production build (it does not, and is off there), that it
          works without @fluixi/devtools installed, or that it needs an extension
structure:
  table row, to append to the existing options table:
    | `devtools` | on in dev | serve the running app's reactive graph, and mark where each
      node was created. `{ external: true }` marks dependencies too |
  then the section:
  1. one paragraph: in dev the plugin puts a small agent in the page ahead of the entry and
     serves what it reports at GET /__fluixi/graph — plain json, so an editor extension, a
     panel or curl all read the same thing. Needs @fluixi/devtools as a devDependency; if it
     is not installed the plugin says so once and stays out of the page. Nothing of this is
     in a build.
  2. the code block, four lines:
       // vite.config.ts
       plugins: [fluixi()],                            // graph on in dev
       plugins: [fluixi({ devtools: false })],         // off
       plugins: [fluixi({ devtools: { external: true } })],  // dependencies too
  3. one paragraph: each node carries the file, line and column it was created at, named
     relative to the project root. A dependency's nodes are left unmarked by default, which
     is what keeps the graph to the code you are editing.
  4. one paragraph: `external` is for working on the framework. It marks node_modules and
     anything outside the root as well, so the graph shows which nodes a library created and
     which the application did — they are flagged `external` and drawn back in the view. The
     application's call site still wins over the wrapper that made the node, so `count` reads
     as the line you wrote it on rather than the line inside signal().
