package:  @fluixi/devtools — a new "## Getting the graph somewhere else" section for the
          README, placed after "Watching an app you did not write" and before "Where a node
          came from"; plus three lines for the API list at the end
audience: someone building a panel, a browser extension or an editor integration
one-line: heading, three short paragraphs, one small code block, three API bullets
verified: 41 tests in packages/devtools; the vite plugin uses both halves to serve a running
          app's graph over http, checked end to end on an example app
do-not-claim: that a snapshot carries write edges (it does not), that a hook installed after
          the app has loaded still works (it does not — the runtime offers once), or that
          two tools can watch at the same time
structure:
  1. one paragraph: `serializeGraph` flattens the graph to json — Sets become arrays, the
     live core node becomes version and state, the reader is dropped — and
     `snapshotToRenderMap` turns it back into something the view draws. `sample()` returns
     what moved, so a delta is the same call with those ids, and `applySnapshot` folds one
     into a graph already on screen.
  2. one paragraph: `installDevtoolsHook()` is for a tool that cannot be imported by the
     app. It leaves a global behind; when the application's runtime loads it finds it and
     hands over its own registration function, so the graph is built from the app's copy of
     the framework rather than the tool's. It has to be installed before the app runs — a
     browser agent at document_start — because the runtime offers once. It works against a
     production build too, without names or locations.
  3. the code block, six lines:
       import { installDevtoolsHook } from '@fluixi/devtools';
       const hook = installDevtoolsHook();          // before the app loads
       // …the app runs…
       hook.snapshot();                  // everything
       hook.snapshot({ partial: true }); // only what moved since the last call
  4. one paragraph: read edges survive the trip; write edges do not exist on an observed
     graph, since nothing records which computation was running when a setter fired.
  5. three bullets for the API list:
     - `installDevtoolsHook()` → the global a tool attaches through
     - `serializeGraph(graph, now?, { ids, removed }?)` / `snapshotToRenderMap(snapshot)`
     - `applySnapshot(graph, snapshot)` — fold a full snapshot or a delta into what is drawn
