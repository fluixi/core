package:  @fluixi/devtools — a new section to append to the existing README
audience: someone using the graph, or writing another renderer for it
one-line: one section, not a whole README. It goes after "How it works".
verified: the flow was run end to end in the playground; a node reported
          src/Counter.tsx:3:16 for the signal declared on that line
do-not-claim: that a node always has a source. It is optional, it is development
          only, and a production build carries none of it.
          do not claim the playground owns any of this. It reads node.source and
          draws it; that is all it does.
structure: heading level 2, titled "Where a node came from". Then, in order:
  1. a graph node can carry an optional source: file, line and column of the place
     the author created it, plus the variable name when the source gave one. Every
     field optional, and the whole thing absent for a node the compiler did not see.
  2. how it arrives, as a short chain — the compiler marks each creation site when
     `sourceLocations` is on, the mark names the file and position from the original
     source rather than the generated output, and the instrumented primitive takes
     the mark and keeps it on the node. Then this block VERBATIM:
```ts
// what the compiler emits in development
globalThis.__fx_source?.("src/App.ts", 10, 15, "count");
const count = signal(0);
```
  3. what a consumer sees. Then this block VERBATIM:
```ts
for (const node of reactor.graph.values()) {
  if (node.source) {
    console.log(node.label, `${node.source.file}:${node.source.line}:${node.source.column}`);
  }
}
```
     say that a renderer needs nothing else — no compiler, no source file, no ast —
     and that file, line and column are enough for a host to decide how to open it.
  4. "Making a node the compiler cannot see" — for a primitive built at runtime,
     call markReactiveSource yourself immediately before it, since the next node
     created takes the mark. Then this block VERBATIM:
```ts
import { markReactiveSource } from '@fluixi/devtools';

markReactiveSource('src/factory.ts', 8, 2, 'fromFactory');
const s = signal(0);
```
  5. close with the two limits: a production build should leave `sourceLocations`
     off and then carries none of it; and one statement carries one mark, so
     `signal(compute(signal(1)))` labels the inner call and leaves the outer bare
     rather than giving it a location that is not its own.
