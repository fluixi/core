package:  @fluixi/devtools — two short paragraphs to append to the "Where a node came from"
          section that already exists in the README
audience: someone reading the graph, or writing a renderer for it
one-line: two paragraphs, no heading, no code block
verified: run in the playground — a component showed as `component App <div>` with
          src/app.tsx:4:7, its declaration
do-not-claim: that a component node is a new kind of reactive node. It is the memo the
          compiler already wraps a component in; the kind only says what it holds.
structure: two paragraphs, at most 90 words together.
  1. the compiler wraps every component in a memo, so the graph sees the wrapper rather than
     the component. A node whose value carries a component's name reports its kind as
     `component` and takes that name as its label, so the graph reads `App` rather than
     `m5`. Nothing about the node changes — it is the same memo, with the same dependencies.
  2. its source is the component's declaration, which the compiler records by name. Two
     components sharing a name in one program are reported without a location rather than
     with the wrong one.
