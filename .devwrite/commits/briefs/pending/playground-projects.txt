files:  playground/src/* (project.ts, link.ts, modules.ts, run.ts, editor.ts, examples.ts,
        Playground.tsx, styles.css), playground/public/logos/mark.png
what:   the playground edits a project rather than a snippet. A file tree adds, renames and
        deletes files; imports between them work, and so does importing the framework —
        @fluixi/core, dom, reactive, jsx and their subpaths. Each file becomes a real ES
        module behind a blob url, linked in dependency order, so import is the engine's.
        The panes resize by dragging, the file tree collapses, the theme follows the rest of
        the sites, and a project persists to local storage and into a shareable url.
why:    before this a single snippet was rewritten by a regex into destructures from a
        four-entry map, so `import { render } from '@fluixi/core'` could not resolve and
        nothing could be split across files. The reactive primitives now come from the
        running reactor through that same registry, which is what keeps the graph honest
        when a signal is created in an imported module.
        Monaco offers no completion inside an import string — it holds models, not a file
        system — so the project's own paths are supplied from the list the linker resolves
        against.
verify: all four examples run in a browser; resolution, ordering and cycle detection
        exercised directly; both splitters and the theme checked
