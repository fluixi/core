files:  packages/compiler/src/transform/props-reactivity.spec.ts
          -> packages/core/src/lib/render/props-reactivity.spec.ts
what:   the props reactivity spec moves from the compiler to core, and loads what it
        compiles by importing it rather than rewriting it to CJS
why:    it reached across the package boundary into core/src, so the compiler
        depended on core while core already depended on the compiler. nx refuses a
        cyclic task graph and killed every build that pulled in docs or start; pnpm
        orders the same graph itself, which is why this went unnoticed for so long.
        importing the compiled module from inside the package resolves its bare
        specifiers to the same instances the spec imported, which is all the stubbed
        module map was doing, and it needs no transformer at all.
verify: spec run, green
