files:  assets/theme.css, docs/src/styles.css, docs/src/routes/index.tsx,
        web/src/routes/landing.css, web/src/routes/index.tsx
what:   web and docs shared no palette before this — each carried its own copy of
        the same tokens, already drifted from each other. assets/theme.css is now
        the one definition both import. The palette itself is near-monochrome:
        ink on paper, hairline borders, no gradient text, no radial glows, no
        decorative window dots. The brand green is kept for three things only —
        the active item in a nav, the focus ring, and strings in code. Links are
        underlined rather than coloured.
        The landing page's feature grid became a list of hairline rows instead of
        a card grid, and gained a stat strip under the hero. A `min-width: 0` on
        the grid items holding a code block fixes an overflow: the `pre` inside
        is `white-space: pre`, sized to its longest line, and a grid child's
        default min-width refuses to shrink below that — forcing the whole page
        wider than the viewport on a narrow screen.
        The docs header no longer lets its action row (version select, language
        switcher, theme button) overlap the brand on a phone-width screen: the
        brand is now flex-shrink: 0, and the two variable-width controls in the
        action row get an explicit max-width and clip instead of forcing the row
        wider than it has space for.
why:    the previous palette read as generated — the same teal-plus-violet-plus-
        gradient combination that shows up across unrelated AI-made sites.
        Stripping it back to two colours used once each is a stronger signal of
        intent than nine.
verify: both sites checked in a browser, light and dark, desktop and at phone
        widths; the overflow and header-overlap failures reproduced and stopped
        reproducing after the fix
