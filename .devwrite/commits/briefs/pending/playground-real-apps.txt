files:  playground/src/examples.ts, project.ts, run.ts, compile.ts, editor.ts,
        index.html, src/main.tsx
what:   a playground project is now shaped like one `npm create fluixi` scaffolds: an
        index.html that names its entry, src/main.tsx that mounts into #app, a component
        beside it, and the fluixi.d.ts, tsconfig.json and package.json a real project
        carries. The preview starts as that html body, so the element the entry looks for
        is really there, and every file is editable.
        Compilation runs the two stages a real app runs — the template transform, then the
        babel plugin. The playground's own root is no longer #app.
why:    the entry used to export a component for the playground to render, which is a shape
        no application has. Reading the entry out of index.html means the project says how
        it boots, the same way it would under vite.
        the `$` intrinsics are resolved by the template transform, not the babel plugin, so
        a project written with $signal met "not defined" at runtime — the playground was
        running half the pipeline.
        both the playground and a project called their root #app, and getElementById
        returns the first in the document, so a project mounted itself over the whole
        playground and left only the preview on screen.
verify: all four projects run; $signal and $memo land in the graph
