subject: one line under 70 chars, about a store being legible in a graph
body:    first paragraph the symptom. Then one paragraph per note below, blank line between
         each — five notes, five paragraphs. Do not merge them into one. No closing summary.

files:  packages/reactive/src/lib/store/store.ts, store.store.spec.ts
what:   a store reports itself as a node, and its key signals attribute to the object that
        holds them.
symptom: a cart of two items filled a watcher's graph with a dozen unnamed signals, each
        pointing at the line that first read it rather than at the store.
notes, one per paragraph:
  - the store node consumes the mark at the createStore call, so it is the one that carries
    the declaration site; key signals inherit it.
  - a key signal is named for its path — cart.items, cart.items[0], cart.items[0].qty — and
    hangs off the object above it, so a list reads as objects rather than loose keys.
  - the signal that tracks which keys exist, made the first time anything iterates, is named
    too. It had no name and no value, so it read as an unexplained empty node.
  - writeKey takes the raw value on the way in. `set({ items: [...cart.items, one] })` spreads
    the store's own proxies back into it, and a store holding its own proxies tracked every
    object twice over: a second node store per object, a proxy wrapping a proxy, and two live
    signals for every key. That is a correctness fix, not only a tidier graph.
  - when a write replaces the array around an item, the item keeps its signals and moves;
    the ones it no longer needs are let go, and what is still reachable is kept.
verify: 33 tests in the store suite, three of them new
