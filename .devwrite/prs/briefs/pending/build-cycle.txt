title:   Move the props reactivity spec out of the compiler
what:    one spec moves from the compiler package to core
         it loads what it compiles by importing it, not by rewriting it to CJS
why:    the spec imported core/src through a relative path, so the compiler
           depended on core while core already depended on the compiler
         nx refuses a cyclic task graph and failed every build reaching docs or start
         pnpm orders the same graph itself, which is why it went unnoticed
         core already depends on the compiler, so the spec is legal there
         importing the compiled module from inside the package resolves its bare
           specifiers to the same instances the spec imported, so no transformer is
           needed at all
verify:  spec run, docs build
review:  nothing else changed: no package.json, no lockfile, no runtime code
         the cycle is pre-existing and blocks #170, which is the first branch whose
           affected set reaches docs and start
